  As the app grew, UI patterns were becoming inconsistent across web and app within the shared design system. Teams recreated similar components in different ways, interpreting spacing, states and behaviours differently. Some features were designed in isolation because existing web components weren't suited to the app. This slowed delivery and created visual and interaction inconsistencies, showing the foundations weren't scaling with the product.
challenge: Establish a scalable, consistent component library that could serve multiple brands and align design with development.

## Design Decisions

### UI Audit

Reviewed screens across brands to map repeated patterns, identifying duplicated components and inconsistent states. Worked closely with developers to ensure components were practical and matched development structure.

<Media src="/images/app-library/audit.svg" alt="Component behaviour and testing audit" layout="panel" />

### Rebuilding Components

Reconstructed patterns from atomic foundations using Figma Variables, reducing reliance on third-party plugins like Token Studio and preventing component bloat. Rolled out gradually to evolve the system alongside the product.

<Media src="/images/app-library/rebuild.svg" alt="Rebuilt components" layout="panel" />

### Usage Guidance

Defined clearer rules for when and how patterns should be used, with a plan to expand documentation over time.

<Media src="/images/app-library/guidance.svg" alt="Usage guidance documentation" layout="panel" />

<Media src="/images/app-library/components.svg" alt="Component library overview" layout="band" />

## Outcome

Migrating to Figma Variables saved approximately 5–6 hours per designer per year, based on 7,609 component inserts. The system now has stronger design-to-code alignment and reliable token syncing across Figma, Storybook and production. It also lays the groundwork for AI-assisted UI generation from real components and connected theming logic across platforms.
